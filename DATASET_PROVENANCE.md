# Dataset provenance and disclosure

**Last updated: 2026-08-16**

> ## ⚠ SYNTHETIC DATA
>
> `cardiac_multilingual_10000_v2.csv` contains **no real patient records**.
> Every row was produced by a script. It must never be described as clinical
> data, patient data, or a hospital dataset in any paper, presentation,
> evaluation or deployment. Any accuracy figure obtained on it is a figure
> about a generator, not about patients.

## `cardiac_multilingual_10000_v2.csv` — how it was made

**Method.** Scripted phrase-bank + sentence-skeleton generator
(`generate_cardiac_dataset.py`, version 1.0, seed `20260816`). The triage
level is sampled first; the complaint text, `ECG_Status` and the vitals are
then each sampled conditional on that level.

**Source material.** All Roman Urdu and English fragments are derived from the
cardiac subset of `triage_mixed_language_dataset_10000_RECOVERED.csv`
(7,855 rows, 887 distinct complaints, 636-word vocabulary) — the organic
dataset this project began with. The Level-4 branch is seeded by the 22
genuine Level-4 cardiac complaints in that file. No Roman Urdu was invented;
real fragments are recombined under twelve different sentence skeletons.

**Vocabulary.** 277 distinct words. This is 2.3× the file it replaces (120)
but well below the organic dataset (782). A phrase-bank generator cannot
reproduce the variety of genuinely human-written complaints, and this gap
should be stated as a limitation rather than papered over.

**Label construction — read before quoting any accuracy number.** In the file
this replaces, `ECG_Status` determined the label almost perfectly (ST
elevation → Level 1 in 1,930 of 1,932 rows). A model trained on it reached
99.1% accuracy from vitals alone while the complaint text contributed
nothing. In v2 the ECG, vitals and text distributions deliberately **overlap**
between adjacent triage levels, so no single feature determines the label and
the text pipeline has real work to do. Expect materially lower — and more
honest — accuracy than the 98.45% obtained on the previous file.

Two constraints are enforced regardless of the overlap, because violating
them would teach the model something clinically false:

- Infarct patterns (`ST elevation`, `Anterior MI`, `Inferior MI`) appear
  **only at Level 1**.
- Heart rate is derived from the rhythm where the rhythm implies one, and
  complaint text that contradicts the rhythm (for example "dhadkan tez"
  recorded against `Bradycardia`) is rejected and resampled.

**Known defect in v2, fixed in v3 (tier bleeding).** v2 drew every phrase
from the bank matching its own severity tier, so the banks were effectively
disjoint and the *vocabulary* gave the label away: 101 of 277 words occurred
at exactly one triage level, 76% of rows contained at least one of them, and
a bag-of-words model reading only the complaint text scored 99.9%. That is
the same class of defect as the ECG determinism this generator exists to
remove. In v3 a row usually draws from its own tier but sometimes from a
neighbouring one, with probability falling off by tier distance, so every
phrase can appear at several levels with a frequency gradient instead of a
hard boundary. Red-flag phrases (syncope, "bardasht se bahar") are blocked
from bleeding down into the low-acuity tiers, and explicit reassurance
("rest se theek ho jata hai") is blocked from bleeding up. Sentence shape is
bled the same way, since in v2 only Level 4 could produce the benign
skeletons.

Measured effect:

| dataset | single-level words | rows containing one | text-only BoW accuracy |
|---|---|---|---|
| v2 | 101 | 76.0% | 99.9% |
| **v3** | **0** | **0.0%** | **69.0%** |
| recovered organic (reference) | 4 | 1.8% | 47.4% |

**Reproducing it.**

```bash
python generate_cardiac_dataset.py --out cardiac_multilingual_10000_v2.csv
```

Same seed → identical file. Machine-readable provenance is written alongside
the CSV as `cardiac_multilingual_10000_v2.csv.provenance.json`, and
`train_embedding_pipeline.py` copies it into `model_manifest.json` so the
disclosure travels with any model bundle trained on it.

## Unknown-provenance file

`cardiac_multilingual_10000.csv` (the currently deployed model's training
data) arrived with no generator script and no prompt. Forensically it is
scripted slot-filling — 120 distinct words across 10,000 complaints, uniform
punctuation, zero duplicate rows, zero Level-4 rows — but the exact process
is not recoverable. **It should not be cited as data of known provenance.**

## Required disclosure text

Suggested wording for a paper's data section:

> The evaluation dataset is synthetic. Complaints were generated by a
> phrase-bank and sentence-skeleton script whose vocabulary is derived from
> an organic Roman Urdu/English triage corpus of 887 distinct cardiac
> complaints. Triage labels were assigned by construction rather than by
> clinician adjudication, and the ECG, vitals and text distributions were
> configured to overlap between adjacent acuity levels. No real patient
> records were used. Results therefore characterise the processing pipeline
> and must not be read as clinical validation.
